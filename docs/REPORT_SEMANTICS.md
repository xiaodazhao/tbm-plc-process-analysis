# 施工语义表达层

## 作用与边界

`tbm_process/reporting/semantics.py` 位于冻结版 PLC 分析结果和后续大语言模型之间。它只读取完整事实契约，不重新分段、不修改四阶段结果、不调用大语言模型，也不根据参数变化诊断地质、刀具或设备故障。

处理分为四步：

1. **事实提取**：从 `structured_full_days/*.json` 提取全日、施工过程、参数响应和数据质量候选事实；
2. **筛选与组织**：按可配置规则选择代表性过程、组织时间相邻的作业、比较口径一致的运行片段，并合并重复响应；
3. **工程表达**：用确定性中文模板生成面向现场人员的事实句；
4. **证据关联**：为每句话保留冻结结果字段、内部编号、源文件、原始行号、统计口径和质量限制。

四步对应的主要公开函数为 `extract_candidate_facts`、`select_and_organize_facts` 和 `express_engineering_facts`。规则集中保存在根目录 `report_semantics_config.json`。交给 LLM 的输入只由后续日报量化层生成，语义层不再保留旧版 LLM 输入分支。

## 活动证据与代表性过程选择

语义层明确区分机器运行活动、推进相关运行响应、证据充分的掘进作业和可确认进尺。冻结分析中的循环标签只作为候选来源，不会直接翻译成“持续掘进”。

- 导向盾首里程增加，或累计进尺与质量控制后的速度积分同时达到配置阈值且相互一致时，允许表达为掘进作业；
- 只有很小的距离证据、距离证据冲突或没有局部进尺证据时，保守表达为“推进相关运行活动”；
- 单段里程变化为零不会自动排除机器活动；
- 局部进尺数值不写入正文，今日进尺仍只采用全日导向盾首里程首末差。

语义层不再固定选择最长五段，也不机械输出全部内部循环。当前透明规则综合使用：

- 作业持续时间；
- 推进速度、总推力和刀盘扭矩的有效数据比例；
- 是否具有可比较的持续运行片段；
- 时间相邻关系和施工时段覆盖；
- 参数变化的持续性与多参数证据。

单个区间导向盾首里程变化为零不是排除条件，因为米级里程分辨率不足以否定短时真实推进。没有足够证据的日期可以不输出主要过程；没有达到筛选要求的响应可以为空。

时间相邻的过程只有在间隔、总跨度和参数表现均满足规则时才组织到同一条事实。合并事实保留每次活动、各次间隔、总时间跨度和累计活动时长，并明确标记为间歇活动；当前单条汇总跨度不超过 4 小时。

“较高”“较低”只在同日、具有可比较持续运行样本的过程之间判断。完整 JSON 保存当前值、比较群体、统计指标、上下阈值、判定结果和单位状态。趋势正文使用“整体呈上升/下降趋势”，不表示每个采样点单调变化；高波动表达为“波动程度较高”，不解释为故障。

运行响应只从正式施工时段内选择。启动、上升和下降中的预期参数变化不会自动升级为重点响应。重叠且参数方向相同的响应按时间重合比例去重。

## 正文与证据分离

读者文本不出现：

- `A060`、阶段编号等内部标识；
- “有效推进区间”“候选片段”等分析术语；
- `startup`、`stable` 等四阶段标签；
- 速度积分、评分、相关系数；
- 未确认单位的参数绝对数值。

这些信息保存在 JSON 的 `selection_metadata` 和 `traceability` 中，供审计和事实核验。

## 进尺、状态与单位

“今日进尺”只使用 `overall.chainage_change_m`，即导向盾首里程首末变化。若记录不足，则明确输出无法计算，不用速度积分或其他累计字段替代。

状态时长来自冻结结果 `machine_states.duration_seconds`，按有数据支持且经过采样时长封顶的记录统计。硬采样缺口不会被推定为停止时间。

当前推进速度、总推力和刀盘扭矩的工程单位尚未由 PLC 点位表确认。绝对统计值保留在结构化证据中，并标记 `allowed_for_numeric_reporting: false`；正文仅使用同日、同口径片段之间的相对高低。刀盘转速还存在暂定字段映射，因此不进入当前读者参数结论。

## 输出

每一天输出两份文件：

- `<date>.json`：结构化工程事实、中文表达、选择记录、质量限制和追溯证据；
- `<date>.md`：按“当日施工概况、掘进过程与运行表现、值得关注的运行情况”组织的中文事实；

运行指定日期：

```bash
conda run -n LLMenv python scripts/build_report_semantics.py \
  --dates 2023-10-28 2023-11-03 2023-11-30
```

处理前 30 个日期并验证：

```bash
conda run -n LLMenv python scripts/build_report_semantics.py \
  --max-days 30
conda run -n LLMenv python scripts/validate_report_semantics.py
```

默认语义输出位于 `outputs/report_semantics/`，验证报告位于 `outputs/validation/`。不提供 `--dates` 或 `--max-days` 时处理全部冻结日结果。批量验证检查进尺口径、内部术语、无依据因果判断、证据覆盖和重复句；它是内部一致性检查，不是工程语义准确率。

## 日报量化层

`tbm_process/reporting/quantitative.py` 在工程语义 V3 之后增加日报级量化整理。它只读取冻结完整
结果、冻结逐点结果和 V3 工程事实，不重新计算运行状态、循环、四阶段或事件边界。

量化层生成两种独立输入：

- `formal`：只发布单位和口径已经确认的数值；未确认工程单位的参数仅保留有效样本信息和定性结论；
- `research_preview`：允许展示质量控制后的原始 PLC 记录值，但必须显著标明工程单位待核实，不能冒充正式工程量值。

运行和复核指定日期：

```bash
conda run -n LLMenv python scripts/build_quantitative_daily_report.py \
  --date 2023-11-03
conda run -n LLMenv python scripts/validate_quantitative_report.py \
  --date 2023-11-03
```

输出位于 `outputs/report_quantitative_v1/`。其中 `*.deterministic.md` 是确定性核查预览，
`*.llm_request.*` 是待提交给模型的完整请求。两者都不表示已经调用 LLM。
2023-11-03 的详细字段、单位、计时和质量计数核查见
`docs/QUANTITATIVE_REPORT_AUDIT_2023-11-03.md`。
