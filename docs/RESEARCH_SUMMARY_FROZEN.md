## 1. 一句话说明现在在做什么

本研究把TBM运行记录、地质预报、历史现场素描和设计资料，整理成有时间、里程、来源和质量限制的工程事实。程序先计算施工过程和可描述的机器表现，再让大语言模型选择、组织和表达这些事实，最后通过程序核验、有限修订及固定排版，形成可追溯的完整施工日报。

它不是让模型直接看原始CSV和几份PDF“自由发挥”，也不是把一批统计数字套进模板后就结束。程序负责可复算的计算、资料准入和关系约束；模型负责事实取舍、段落组织和自然语言表达。两者职责明确分开。

目前最合适的研究定位是：**多源施工事实组织与受约束的整篇日报生成及验证**。工程响应分析是生成依据，不是另行训练的围岩分类器；证据图是关系和来源约束工具，不是已经证明能推理地质致因的知识引擎。

## 5. PLC事实究竟如何计算

### 5.1 时间支持不是“样本数乘20秒”

每条记录有真实时间戳和保存的`sample_dt_seconds`。该量来自冻结质量控制：有效向后支持按真实时间间隔计算，受最大样本支持限制，硬缺口不被填成工作或停机。具体数值配置见`config.json`，最大样本支持120秒、硬缺口大于180秒。

日报读取这些保存的支持，不重新发明时长。累计推进时间是符合既有推进状态的支持时长之和；非推进时间是已观测其他状态的支持时长。运行平台的首末跨度不是累计推进时间。

新增日覆盖对账为：

`日历日未覆盖时间 = 86400秒 − 冻结有效支持时间`

`覆盖率 = 有效支持时间 / 86400秒 × 100%`

程序对支持区间取实际补集，区分日界端点和内部缺口，要求两者与原日统计精确对账。没有记录的时间不自动分配给停机。

### 5.2 日进尺与分段进尺不是一个指标

| 指标 | 真实口径 | 特别限制 |
|---|---|---|
| 日进尺 | 当日有效导向盾首里程末值减首值 | 整数来源只表示整米级读数，正文写约数 |
| 平台内部进尺 | 原`开累进尺`平台有效首末差，沿用已有采用/拒绝规则 | 检查回退、突跳和缺失，不用速度积分代替 |
| 活动进尺 | 合格平台内部进尺的组合 | 不分摊跨平台边界变化，不强加成日进尺 |
| 日推进效率 | 日进尺 / 累计推进小时 | m/h，不是瞬时推进速度或综合设备效率 |
| 活动推进效率 | 被采用活动进尺 / 对应累计推进小时 | 进尺不可信则不报效率，不填0 |
| 推进时间占比 | 推进支持时间 / 有效状态支持时间 | 不是以24小时作为隐含分母 |

整数日进尺来自原始盾首字段，不是渲染时把小数截掉。未经验证的累计进尺端点差不能替换已经冻结的日进尺定义。

### 5.3 平台与四阶段

平台优先检测使用60秒平滑后的速度、推力、扭矩和转速活动投票；活动下限分别0.5mm/min、1000kN、100kN·m、0.5r/min；核心要求至少两项活动，核心至少180秒和8条记录。内部连接120秒、边界扩展180秒，不能跨硬缺口。完整参数见`configs/platform_analysis.json`。

平台内部复用既有四阶段器。稳定性主要看推力、扭矩和质量受控贯入度，贯入度不足时有明确回退。典型判据为180秒窗口、至少5条，稳定阶段至少180秒和8条；归一化标准差≤0.10、分钟斜率绝对值≤0.04，三参数至少两项通过，活动水平≥0.35。

四阶段为启动、上升、稳定、下降。允许无稳定阶段，不强行四等分。

历史平台配置还带`experimental_not_frozen`名称，四阶段配置带`frozen`名称。本次冻结固定的是当前实际使用的代码和参数快照，并没有偷偷将历史元数据改为“已获准确性验证”。论文应如实说明平台优先预处理和继承的四阶段方法。

### 5.4 响应特征的样本集合

`response_features.response_samples`的基础集合是：既有稳定标签 ∩ 既有推进状态 ∩ 速度质量可用 ∩ 速度>0.5 ∩ 推力、扭矩为正且有限 ∩ 存在映射标志时要求核心位置确认。

速度、推力、扭矩的基础描述不额外强制所有派生性能条件，但既有推进状态本身可能已依赖转速，因此转速缺失仍可间接减少基础样本，不能声称已完全摆脱转速影响。

统计包括数量、中位数、均值、P10/P90、极值、支持时长、平台构成和精确源行集合。其中分位数和中位数是按样本计算；时长另按真实支持求和，不能把两者混成时间加权分位数。

### 5.5 时间窗口趋势与组合现象

连续窗口通常为300秒，遵守阶段、平台、来源行连续性和硬缺口边界。趋势复用`dynamics.descriptors.trend_descriptor`：

- 用真实分钟时间计算Theil–Sen稳健斜率。
- 计算时间与参数的Spearman相关。
- 首末各四分之一记录的中位数作为窗口边缘摘要。
- 尺度为`max(P90−P10, 0.05×abs(中位数), 1e−9)`。
- 原趋势归一化变化量为`(末四分之一中位数−首四分之一中位数)/尺度`。
- 当其绝对值达到0.15且相关绝对值达到0.45时，给升/降方向；去趋势MAD描述波动。

这些是描述筛选阈值，不是统计显著性、安全值或异常概率。趋势标签中的`stable`在正文不自动解释为设备正常或无波动。

局部紧凑图若显示百分比，使用另一明确公式：

`100 × (末四分之一中位数−首四分之一中位数) / abs(首四分之一中位数)`。

它不是原来用分布尺度归一化的`relative_change`。首值为0不硬算百分比；窗口值也不是两个瞬时采样值。

### 5.6 代表性现象选择

`evidence_graph.response_analysis.time_window_analysis`保留全部窗口，只从支持充分、原行可复核、属于主要活动且已有趋势的窗口选例。叙述示例至少12条记录及180秒支持，优先覆盖不同活动的同向组合，再考虑反向组合，最多3个；没有条件可不选择。

现有选择还优先使用扭矩CV≤0.25的易读窗口，但较高CV窗口仍留在完整记录中。这个偏好影响“正文代表性”，不等于排除真实异常或证明CV≤0.25就是正常。今后应通过独立覆盖评价确认是否遗漏值得关注的高波动现象，不宜继续凭感觉加规则。

### 5.7 派生性能指标的实际地位

代码已有：`PR=v/n`；`FPI=总推力/(70×PR)`；理论机械比能`SE=(F/A+2πT/(A×p))/10^6`，其中力、扭矩、面积、每转贯入均换成相容SI单位。

这些实现只在稳定、推进、转速映射可用、运动与负载为正等条件下计算，并有分母保护。FPI采用总推力和安装刀数，不是实测每刀有效力；SE不是总电耗。它们共享输入，不是三条相互独立的地质证据。

最新接受报告的重点是速度、推力、扭矩、转速与时间/位置组合，没有把上述派生量包装成严格反演地质参数。这些指标可作为有条件候选，不应将公式可计算等同于工程解释已验证。

## 6. 地质证据如何进入当天报告

### 6.1 时间准入

日报日D的截点为D日00:00，时区Asia/Shanghai。日期信息的来源和精度保留。

`geology_store.time_policy.time_decision`：有已验证的带时区实际可用时刻时，要求该时刻早于截点；只有日期时，采用用户确认可用日或有来源的提交日，并要求日期早于D。封面日期、文件名日期不能自行等同实际收到时间。同日而无时刻不默认准入。

当前SQLite的270条文档没有非空`available_at`，主要依赖日期策略；214份当前素描具有用户确认可用日期，但刷新统计的明确观测日期记录为0。部分JSON有报告日期，不应把报告日期改叫现场原始观测时刻。

这是一种可复现的回溯研究约定，不等于掌握了每份报告真实传递时间。设计背景另按用户确认的施工前资料策略准入。

### 6.2 空间准入

先核对已准入的当日盾首起终点，统一到DyK数值里程，再计算资料原范围与当日范围、前方20m窗口的真实交集。

区间证据要求正长度交集，不能仅因共享端点就跨到下一区段。风险点按边界归属规则处理；母区段与原文局部里程均保留。F36、掉块点、出水点等不能因同份PDF中存在另一预报段而自动扩展范围。

前方覆盖按合格区间并集计算，不能把两个重叠来源的长度直接相加。预测未覆盖不等于没有设计地质信息，更不等于前方没有风险。

盾首里程与实际掌子面位置偏移尚未独立核实，程序未擅自加固定偏移。日报正文可写“里程”，研究说明中应交代配准限制。

### 6.3 证据属性与相对表述

预测、历史观察、推断、设计和建议在事实角色中分开。TSP/HSP不是当日揭示；素描既有结论也可能有推测及建议，不能全称实测。

原文“较前一段变好/变差”只能相对于原预报报告自身的前一预测段，不自动指PLC切出的前一子段。参照不清时可以只用绝对岩性、裂隙、破碎、水文属性。

不同来源围岩等级差异保留，不裁定其中一个正确。相同来源被多个PLC范围引用，仍是一条来源，不能当成多个独立地质样本。

## 7. 图、分析结果与统一事实包的区别

### 7.1 证据图实际做什么

当前图用JSON形式存节点和边，并不要求Neo4j。核心节点为：

`GeologyDocument → GeologyFact → ConstructionSegment ← PLCResponse`，以及`EngineeringComparison`。

关系包括`HAS_FACT`、`COVERS`、`OBSERVED_AT`、`OVERLAPS_WITH`、`MEASURED_OVER`、`COMPARES`、`DERIVED_FROM`。来源、事实、真实区间、响应和比较由ID连接。

2024-02-28保存图中的实际数量为：

| 节点/关系 | 数量 |
|---|---:|
| GeologyDocument | 239 |
| GeologyFact | 3024 |
| ConstructionSegment | 1340 |
| PLCResponse | 1 |
| EngineeringComparison | 278 |
| HAS_FACT / COVERS / OBSERVED_AT | 3024 / 1745 / 328 |
| COMPARES / DERIVED_FROM / OVERLAPS_WITH / MEASURED_OVER | 285 / 285 / 21 / 1 |

这是该运行保留的目录图和分析关系数量，包含背景资料；不代表这些节点全部通过当日日报准入，更不代表每条关系都是已验证地质语义关系。

当前图可提供区间组织、来源链接、关系候选及边界/ID检查。TSP/HSP属性比较主要基于既有字面提取与规则；本默认流程没有再调用LLM发现新的地质关系。不能把旧独立关系实验的能力当成默认流程已启用。

### 7.2 图没有替代哪些东西

气体、设计检索和新增报告组织事实还会在`assembly/enrich_*`阶段加入统一包，不保证每一个新增事实都另建图节点。不能把“统一包有此事实”说成“图谱已有这种节点和推理”。

Planner并不读取完整邻接表直接作图算法推理。程序先将关系和分析结果编译为可读的事实，再提供给模型。图主要通过证据组织间接影响生成，增量价值仍须做等输入的消融。

图中有路径只证明“可以沿ID追溯”，不能单独证明原文实质支持该句，不能把空间对应推成统计规律或因果。

### 7.3 统一包的字段

每条事实一般包括：`fact_id`、`section`、`canonical_text`、`data`、`sources`、`required`、`role`。

- `data`保存完整数值、时段、区段、比较对象、样本及限制。
- `sources`保存原文件/分析文件路径、SHA，适用时含页码、原文和源行。
- `canonical_text`是程序组织的有依据文字摘要，不是LLM已经核实的真值。
- `required`表示信息覆盖义务，不意味着必须逐字照抄。
- `role`控制观察/预测/设计/条件参考/计算现象的表达性质。

2024-02-28共45条事实，分布为第一章5、2.1两条、2.2九条、2.3七条、3.1十条、3.2两条、3.3十条。完整包和实际请求都保存，不能只交最后精简输入。

### 7.4 LLM真正收到什么

`writer.model_facts`给模型的主要是事实ID、节、文字摘要、必选标志和角色。最新组织层用`writing_view`进一步删除重复免责声明、审计样本数及无需正文复读的细节，保留有依据的数字和限制。

因此：**完整PLC与地质事实共同参与统一准备和整篇生成，但不是把完整逐点数据、所有data字段、PDF全文及完整图原封不动送给模型。** 真实请求还含章节、政策和图表展示契约；写作请求含已检查计划。正文通过事实ID回连完整证据。

精简视图有数字不得超出完整摘要集合的检查，但这仍不能证明所有语义都保留。应在实验中评价摘要是否遗漏重要事实。

## 8. 地质—机器响应分析到底是什么层次

已有两种描述途径：

1. 原预报边界产生不重叠分析范围，用相应合格稳定记录比较邻近区段。
2. 当没有不同地质区段可比时，选择共同既有预报背景下位置不重叠的前后主要施工活动，描述机器响应差异。

后者由`organization.operating_comparison`确定性完成：取足够样本/支持、至少两个可用观测里程、原预报完整覆盖且前后时间和位置分离的活动，按“最早参考、最晚当前”选择，不按最大差异挑选。进尺调查涉及的位置平台被排除；基础统计复用`metric_summary`和`compare_responses`。

相邻或前后中位数变化为`100×(当前−参考)/参考`。同时保留样本数、支持、平台构成、转速和质量。

严格同工况比较要求的`rpm_set`、`advance_speed_set`尚无已验证控制字段，配置中的`verified_control_fields=[]`。转速或推力中位值相近只是诊断，不会升级为已控制操作条件。

因此当前已实现的是：**机器现象 + 来源地质背景 + 有限制的描述性空间对应**。尚未实现并验证跨独立地质区段的可重复统计规律，更没有地质因果机制结论。

## 9. 气体与设计参考如何工作

### 9.1 气体统计

`gas.good_samples`要求数值有限、非负、逐行气体映射状态合格、非重复/逆时记录；零值保留。负值作为不合格读数处理，不解释为负浓度。

气体自身采用真实向后支持，超过60秒的间隔不支持，不补末条20秒；这与PLC原状态支持是两个明确口径，不能不加说明地互换。

输出各气体数量、有效时长、最小/最大、时间加权均值及分位数。CO2、SO2配置900秒完整覆盖的时间加权均值，H2S配置采样值参考；NO、NO2、CH4当前没有独立采用阈值，只统计。

配置引用GBZ 2.1—2019条目及20℃、101.3kPa换算`ppm=mg/m³×24.05/M`，不代表本轮重新完成全部适用标准审查。鉴于单位与仪器状态尚未独立确认，只能称**按既定研究口径与参考值比较的关注时段**，不能用于正式安全报警、人员暴露合规或通风控制。

### 9.2 与运行状态的描述性对齐

`front_analysis.gas_operation_analysis`按时间戳和来源行合并气体与冻结状态，不重分类状态。按5分钟时间加权分箱，覆盖至少80%、配对至少12箱且有足够取值变化才算水平/相邻变化Spearman相关。

对先有推进支持的至少15分钟设备停止区间，可查一分钟均值峰值和尾部5分钟观测带。符合平坦性、覆盖及连续5分钟落带等条件时，才给观察性回落时间；条件不足保留未观测到，不编造等待时间。

这是离线回顾，需要观察同次停止末端；不是实时预测，也不是恢复安全的时间。设备停止不是现场所有工序停止，未记录通风运行不能推断通风不足或有效。

### 9.3 设计条文检索

本地模型`BAAI/bge-small-zh-v1.5`与SQLite词法检索结合，采用RRF，常数60，候选40、每情境最多2条。模型版本固定，向量本地计算，不将设计文档发给嵌入服务。

随后从原PDF同页/同栏扩展完整句，校验SHA、出处、适用地点和条件，排除运营期或不相干灾害措施；气体不引出除尘，SO2不自动引出甲烷防爆。

检索相似度不是适用概率。正文必须写“设计文件针对…提出…可供参考”；前提未确认时用条件句，不记为现场已经执行，不新增支护规格或保证效果。

## 10. 内容规划：规则与LLM各做什么

规则先决定：可用时间、真实交集、质量准入、指标口径、主要活动、代表窗口、必须覆盖的事实、所在章节和允许表达性质。规则也提供先算好的方向与变化，不让LLM计算百分比。

LLM再决定：哪些可选信息值得写、哪些合并、怎样安排自然段、怎样用一个运行现象组织多条来源、哪些不写及原因。每段用`purpose/fact_ids`形成结构化提纲。

`writer.validate_plan`检查七节顺序、未知ID、章节归属、候选是否都有去向、必选事实是否被选、选用与省略是否互斥、省略理由是否非空。

它不证明段落逻辑最优、没有隐含重复，也不证明必选事实的实质含义都写全。规则已经限制了候选和章节，因此这是**规则约束下的LLM组织规划**，不能描述为模型从原始海量数据自主发现全部重要事实。

近期修复了一个真实接口矛盾：同一日效率事实在第一章和2.1被重复设为必选，形成提纲覆盖冲突。只有数据和标准文字完全一致时，将重复`DAY_RATE`设为可选，第一章的对应必选信息仍保留。不是为了过检删掉唯一事实。

## 11. 生成、编辑、核验和修订

### 11.1 生成与编辑

DeepSeek返回结构化JSON：每节包含自然段文字及支持事实ID。它不生成Python统计、不识别新平台、不绘曲线，也不直接设计HTML排版。

请求模型默认`deepseek-v4-flash`，温度0.1，JSON输出，生成上限8000Token、编辑上限7500Token，记录实际返回模型标识。实际别名可能为`deepseek-flash`，论文和成本记录必须同时保存请求与返回值。

默认流程先生成完整草稿，再有一次整篇编辑。这个编辑是常规步骤，不仅在发现事实错误时才运行。它可合并/改写多个段落，因此不能把所有编辑变化都称为“局部事实修复”。

### 11.2 正文程序核验

核验器实际覆盖：章节和支持ID、事实所属节、支持中的数字字面集合、围岩等级字面、部分因果/安全/措施断言、预测冒充揭示、历史冒充当天、前方覆盖矛盾、部分活动进尺与精确时段绑定、进尺调查中的无依据原因、计划信息覆盖。

活动表已由源SHA和渲染检查覆盖的`ACTIVITY:*`事实，可只在表格展示，不强迫正文复述；其他计划支持仍需保留。这解决了“为了通过覆盖把表格再抄一遍”的问题。

**重要局限：当前默认`validate_text`不是完整原子事实语义判定器。** 数字检查主要是成员关系，不能保证每个数字角色、正负号、比较参照和复合句所有分句都正确。正则检查也可能被换一种说法绕过。来源ID有效，不等于引用真正支持这句话。

默认主流程没有额外运行一个独立LLM语义裁判并得到客观正确标签。源码虽存在相关请求分支，是否实际调用要看日志；当前主要是模型编辑和确定性规则。输出明确保留`semantic_status=REVIEW`及空人工判断。

### 11.3 定向修订的真实实现

编辑后检查失败，程序把错误、事实与当前稿送给模型，要求只改有问题段落、其余保留，但模型仍返回完整JSON。程序保存`revision.diff.json`、前后正文、原因并再次检查；最多一次，仍失败停止。

因此它是**通过指令限定范围并保存差异的有限修订**，不是对句子建立不可变补丁约束的严格编辑算法。默认全文路径仍可能改到其他内容，事实ID覆盖也不等于所有正确原子信息被保留。正式实验必须单独检查新增错误、删除重要信息和非目标改动。

历史针对前两章的定向路径有显式`section_ids`，会核对未处理章节未变，但不是默认整篇生成方式。

### 11.4 成品检查

固定HTML/CSS、程序表格和真实曲线一次渲染成PDF；核对正文段落、表格数据、来源支持、文本越界和生成页数。`PDF_text_same_as_checked_model_text`表示所检查模型正文完整出现在交付PDF，不等于模型正文事实已由专家确认。

最新报告正文集中必要口径；来源索引和历史照片另附，保持可读性，不用逐段免责声明撑满正文。

这是同一预报背景下的施工运行差异，而不是两组独立地质试验。位置范围是合格记录的观测外包，不是精确开挖长度。操作给定值、刀具状态和精确掌子面位置未控制，不能推出地质导致速度下降。

### 12.4 地质覆盖、历史记录和气体

前方窗口DyK1015+251至+271，合格HSP覆盖前6m，剩14m无准入超报；设计背景覆盖20m。历史素描可用日期2024-02-26、范围DyK1015+197至+227，不记为当日新增揭示。

按既定研究规则出现3段SO2关注时段，最大完整15分钟均值分别7.5137、12.5857、16.7387ppm，采用参考值约3.7539ppm。关注区间由评价窗口终点组成，不是说区间每个瞬时值都超过参考。

SO2与速度的5分钟水平/变化相关分别−0.09/−0.05。设备05:06:10进入停止后，06:13:10仍出现一分钟均值峰22.7238ppm，距停止67分钟。本日未取得符合既有规则的可报告稳定回落时间。无通风状态记录，不作通风因果解释。

### 12.5 报告表达和调用记录

最终三章PDF3页，正文仍为10.3pt；历史照片和完整来源另附。与保存的五页基线相比，正文字符2960→2070，第三章四类重复防御短语计数6→1。

这是单个开发案例的可复算表达变化，不是独立人工可读性评分。页数减少也不是研究有效性的主指标。

本次质量开发真实新增8次模型调用，包括前一轮2次失败提纲尝试和后续6次生成/编辑/组织修订；输入60,165Token、输出16,956Token。最终稿复用有来源记录的初始计划，经过多轮开发修订，不是冻结后一次成功生成的无偏样本。

这些Token不能当稳定每日报告成本，不能混入将来的正式实验成本。账户实际人民币费用未在此独立核实，不能根据旧价格编出金额。

## 14. 当前最有价值的技术机制

1. **带时间、空间和表达属性的多源事实准入与统一组织。** 它比直接喂资料多了可复算的范围、来源和信息性质控制。
2. **先计算机器现象，再进行关系约束下的整篇内容规划。** 趋势和组合不是模型临时猜的，计划有ID、覆盖和省略义务，可审查取舍。
3. **生成到成品的一致性链与有限修订记录。** 事实、计划、正文、图表、来源和交付PDF有可检查连接，不只留下一个好看的PDF。

这些是可检验的研究设计，不自动等于新理论或优于已有方法。JSON、RAG、图谱和LLM等名称本身不是贡献证据。最有说服力的论文贡献，需要在相同输入的对照和独立事实评价中证明这些机制减少了什么错误、保留了什么信息、付出了多少成本。

## 15. 当前仍存在的关键限制

- 缺少独立人工工程事实标签，当前核验不能代替专家。
- 现行数字核验对角色、符号、复合语义不完备，规则PASS不是句子完全正确。
- 默认编辑会改写整篇；真正局部性和信息保留尚需独立测量。
- 最新质量标准大量开发于少数日期；不可把这些日期作为完全未见测试集。
- 素描SQLite旧路径与运行刷新JSON不一致，迁移时需同时保留当前来源和策略。
- 气体ppm为用户指定，仪器量程/标定/独立单位证据不足，不宜提出正式安全效用主张。
- 盾首与掌子面配准、操作控制给定、维修刀具记录不足，不能声称地质因果或故障诊断。
- 图谱有助组织，但其相对平面事实表的增量价值尚未由严格消融证实。
- 同一长预报背景内的多段PLC不是多个独立地质样本。
- 最新版本完整批量成功率、自动修订收益、平均Token和工程人员可读性仍待冻结后实验。

这些不能笼统说成“只差写论文”；其中一部分是方法能力边界，另一部分才是尚待实验验证的效果。

## 16. 方法章节怎样组织

建议围绕整份日报，而不是只写地质规划：

### 3.1 总体框架与任务定义

定义输入、截点、输出三章及“支持事实/必需信息/研究限制”。将确定性分析与生成式表达分开。说明离线回溯日报，不宣称实时预警。

### 3.2 PLC质量控制与施工事实构建

说明逐行字段适配、来源保留、时间支持、平台/四阶段、合格样本、日统计与运行现象。冻结方法可精简写，但要给关键参数和可复现依据，不要把软件包目录当论文结构。

### 3.3 地质及设计资料的结构化与时空准入

写文档/区段/属性/来源表示，时间准入、里程交集、局部风险、预测与历史观察分离，以及设计条文检索的条件控制。来源层的历史提取准确性由独立实验评价，不能仅引用validated。

### 3.4 多源事实整合与工程现象驱动的内容规划

写统一对象、图提供的来源/区段关系、时间与空间现象摘要、必选/候选、计划JSON及规则检查。明确规则选什么、LLM还能决定什么；不要声称LLM直接读取完整图作因果推理。

### 3.5 受约束整篇生成、核验和有限修订

写实际模型输入视图、结构化输出、支持ID、数值/范围/性质约束、普通编辑与事实定向修订的区别、停止策略和REVIEW边界。

### 3.6 可追溯成品与复现记录

写Python图表和固定HTML/PDF、表格覆盖契约、原始模型记录、源SHA及正文到PDF一致性。篇幅不足时可与3.5合并，而不是为了六节硬凑一个“创新模块”。

以下段落可以作为方法总述草稿，不包含尚未证明的效果：

> 本研究面向TBM日常施工信息汇总，构建由确定性工程分析和大语言模型表达组成的日报生成流程。系统首先对PLC记录进行字段适配和质量控制，复用施工过程及阶段识别结果构建运行统计与动态响应事实；同时，将超前地质预报、历史素描及设计资料表示为带有可用时间、适用里程和来源属性的证据。程序依据报告日期及施工位置筛选可用资料，并将相应地质背景与已计算的机器响应组织为统一事实集合。在此基础上，模型完成受覆盖义务约束的段落规划和整篇写作，程序检查事实引用、关键数值及部分工程表达限制，并对未通过内容执行有限修订。经检查的同一正文由固定模板与真实数据图表共同渲染为HTML和PDF，保留输入、规划、生成、修改及来源校验记录，以支持独立审查。

论文中不要提前写“显著提高准确率”“验证了地质—机器耦合规律”“实现智能故障预警”或“完整复现某事实评分算法”。这些均不由当前证据支持。

## 17. 下一步只做什么

先确认冻结快照与独立评价口径，再开展小规模接口验证、独立事实标注和相同输入A–D对照，最后才扩大样本。具体设计见`EXPERIMENT_PROTOCOL_DRAFT.md`。

不建议继续添加Agent、多模型网络、地质三维建模、新安全等级、更多未经验证指标或再一套日报入口。当前瓶颈不是功能数量，而是**现有机制到底带来多少可靠、可独立验证的价值**。
