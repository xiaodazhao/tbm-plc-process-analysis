# PLCResponse 与多源候选关系实验

这是显式启用的报告输入实验，不替换冻结PLC清洗、状态、平台或四阶段算法，也不修改历史日报。

## 实际执行链路

1. `scripts/run_response_relation_pilot.py`只读打开现有SQLite，按施工日期导出时间准入的地质资料。
2. 复用`reporting_v2.facts.build_facts`读取已修复采样、平台及阶段结果，生成旧口径事实，原样保存。
3. `response_features.build_response_features`新增逐指标统计范围和动态事实，作为`PLCResponse.features_v2`附加字段；原`summary`、`baseline_reference`不替换。
4. `relations.build_candidates`按已合格的事实ID、日期、线路、里程重叠构建候选。最多16条，按类别轮转；不是风险筛选。
5. 可选DeepSeek调用只提出语义关系。程序核查ID、原文引用、时空条件、角色、禁止因果表达。通过者仍是`REVIEW`。
6. 统一Evidence Pack包括PLC概况、全部平台证据、逐指标与窗口事实、地质预测和历史观察、程序关系及模型候选关系。实际写作子集和省略记录另列，完整证据不删除。
7. 同一Planner/Generator配置完成六章结构化计划与正文；核查真实模型文字；C组复用B组原始计划和草稿，至多一次局部修订，再核查及检查信息保留。
8. 复用原有HTML/PDF渲染器与真实曲线。PDF文字逐句对照已核验的同一份narrative，不使用另一份模板正文替换模型文字。

## 样本口径

基础指标为推进速度、总推力、刀盘扭矩：原有稳定标签、推进状态、速度质量合格、速度大于既有0.5阈值，正且有限的推力和扭矩。若存在核心映射确认标志，还须通过该标志。

转速统计另要求原有转速质量、既有0.5转速阈值、逐行来源已解析。PR、FPI、SE再采用原有PR分母保护等全部性能条件。基础指标不放宽核心字段质量，不把未解析转速的记录重新判为推进。因此拆分后未必增加样本数。

各指标保留独立count、P10/中位数/P90、样本支撑秒数、精确源文件及行号、单位及确认依据。样本分位数不是按时间加权；支撑秒数不是首末跨度，更不是连续推进时长。

## 动态与区段比较

- 复用原有300秒、不少于8条且首末跨度不少于180秒的连续窗口，以及原有Theil-Sen/Spearman/去趋势波动规则。新路径额外在源文件切换处断开；旧函数默认参数保持原行为。
- 不跨原平台、阶段、行号缺口或硬时间缺口拼接窗口。没有达到窗口条件的部分列为未描述范围，不补造趋势。
- 每个窗口保留速度/推力/扭矩趋势和扭矩CV；符合性能范围的窗口另保留PR趋势。相邻同平台同阶段、连续源行窗口可以描述CV变化，不据此认定异常。
- 描述性比较保留不同区段的客观中位数差和相对于参考中位数的实际百分比，不因推力接近条件未满足就删除推力差异。
- 工况控制比较独立记录转速/推力分位数、平台组成、样本量、支撑时长、里程分辨率及旧中位数门槛。当前控制点位未获独立认证，`verified_control_fields`为空，故明确为`not_established`，不是已经控制了操作条件。
- 0.5/1/1.5倍旧参数的敏感性结果仅说明试验阈值影响，不能冒充行业或安全标准。
- PR为速度/转速；FPI使用PLC总推力与70把刀具；SE为直径10.23m对应的理论机械比能，不是净破岩真值或电耗。单位依据用户确认，尚非厂家独立点位认证。

## 关系与规划的边界

图节点、边沿用既有类型。模型关系放在`EngineeringComparison`节点及`COMPARES`边，固定三类：地质描述比较、预测与观察比较、地质—机器空间对应。无因果边，不以语义相似确认预报准确。

关系必须附两端证据的逐字引用、模型及请求SHA、提示词版本和检查记录。模型可以不选候选；省略理由须保留。程序被预算排除的候选不再要求模型说明，完整清单仍保留在本地。

规划可选择、分段、排序和省略可选事实，不能编造ID或漏掉必选项。若引用某关系，两端事实须同段出现。模型不必引用每一条关系。未选择候选的理由缺失属于规划失败，不静默补造模型理由。

## 真实实验的A/B/C定义

- A：确定性关系 + LLM计划与生成。
- B：相同事实池、模型和采样参数，增加结构检查后仍为REVIEW的语义关系提示，再计划与生成。
- C：直接复用B计划和草稿，经质量核查定位错误；至多一次局部修订，不重新写整篇。

C与B不是两份独立随机生成样本。模型关系同时改变可用组织提示，不改变底层事实池。开发复跑和首次结果分别记录，不能合成同一冻结条件的成功率。

四日选择为开发案例，并非独立统计测试。无参考区段或无当日预测属于证据不足对照，不能称为已经证实机器无变化的阴性真值。

## 验证与局限

`draft_quality`检查实际陈述的引用、计划归属、数字及单位、必要展示字段、预测/观察混淆、连续性和禁止因果等；未完整理解的语义一律REVIEW。数字出现并不能证明它被用于正确字段或完整复合句含义。

局部修订不得改非目标句，不得删除或增加Claim，不得删除原支持ID和已有支持的数字。该保留检查仍不是完整语义或单位含义保留的人工判定。

`scripts/audit_response_relation_pilot.py`独立重读修复后的采样文件，依据精确行号重算统计和公式，并检查原PDF/JSON的SHA与引用。它不调用生成验证器，但仍是程序核对，不代替专家。

人工关系评价表刻意留空。没有人工标签，不报告语义关系准确率、完整事实准确率、预报准确率或方法显著优越性。

## 运行

```bash
python scripts/run_response_relation_pilot.py --mode offline
python -m pytest -q
python scripts/run_response_relation_pilot.py --mode llm --env-file /path/to/private.env
python scripts/audit_response_relation_pilot.py /path/to/run_directory
```

真实调用限DeepSeek官方接口，默认最多24次、SDK重试0次。任务内续跑必须通过`--prior-call-ledger`带上此前全部调用账本，从24次中扣除；`--repair-from`仅对已保存的失败提纲进行一次显式修正并复用关系输出。不要把开发目录中的源代码快照当成额外测试套件，pytest已排除生成输出目录。

凭据仅从用户指定的本机环境文件读取，不写入请求、输出或交付包。
